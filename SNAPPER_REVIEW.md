# Snapper review — published Snap 0.5.1

Official @sayfer_io/snapper 0.19.1, all default detectors, October 8, 2026. A scanner-only tsconfig includes original JavaScript/JSX/MJS source, JSON metadata and the exact published bundle. This configuration does not alter the published artifact. The initial run found no tsconfig and did not scan; that run is explicitly invalid. The configured scan processed 16 files and reported 118 findings. No detector was disabled.

- DependencyOutdated: 67 findings from the full development dependency tree. A separate npm audit --omit=dev reports nine moderate dependency entries, no high or critical entries; these entries propagate the UUID bounds-check advisory GHSA-w5hq-g745-h8pq. The corresponding UUID source module is absent from the esbuild input graph for the published bundle. This establishes an artifact-specific observation, not a claim that the development dependency tree is clean.
- LeftoverTODOs: two comments in bundled upstream cryptographic library code. They remain in the immutable 0.5.1 bundle. Removal would require a new published artifact and version; this submission preparation must not claim the requested cleanup is complete.
- MissingExplicitStrictTypeChecking: one scanner-config finding. strict:true implies the named options, but they are not individually written. It concerns the supplemental scanner config, not an omitted production runtime gate.
- UnhandledPromiseRejection: four findings, duplicating two source catches in the bundle. The catches intentionally preserve absent history and Unavailable connectivity on the informational Home screen. They do not catch transaction proof verification failures or confer reviewed coverage. This is a documented disposition for external review, not scanner approval. Reported line numbers are character offsets for this detector; the bundle catches are lines 3381 and 3390.
- UsedBeforeDefinedArrowFunctions: 44 findings in generated bundle code. Initial inspected examples misidentify an arrow parameter and a call following an initialized local function. All 44 entries were checked against their resolved lexical declarations: each is either not the call callee or has its actual declaration before the usage. The detector conflates different lexical declarations named mod2 in the generated file. The per-entry evidence is in snapper-arrow-disposition.json.

Limitations: several default detectors only support TypeScript; they do not cover every JSX/MJS source file. OriginValidation also reported Not a snap project for the current package shape. The official scan has therefore been run, but scan acceptance remains false and the preparation is not submission-ready.
